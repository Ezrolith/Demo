# Dr. Manhattan — unbiased human playtest
The purpose of this check is to judge **the experience**, not simply pass the developer tests. Use the latest standalone from `codex/bonus-three`, a keyboard/mouse, a normal difficulty setting and sound enabled. Start from **Bonus Levels** without reading the walkthrough.

## First impressions
- Before each objective, write what you think you need to do. Record the first moment you are uncertain, what you try and whether H or companion dialogue helps.
- Compare one scene in the original pier chapter with scenes in **The Last Broadcast**, **The Ninth Minute** and **The Long Summer** at the same audio volume. Judge the rain, radio static, time-reset chime, crowd noise and musical continuity.
- Test all three opening stages with accessibility options (reduced flashing, low screen shake), and note text readability over fire, dark flooring, and temporal sight.

## Progress and difficulty
- Can you complete the avenue *without* accidentally killing anyone? Does the Comedian warning give you a fair opportunity to intervene after his protected opening?
- Is the roof-vent action understandable without the guide? Can you rescue all six residents at normal damage, and distinguish SAFE EXIT from the route to the next chapter?
- In the truck fight, can you recognise which objects are mechanical targets and which is the cab with a person inside? Try to preserve the driver and note how fair its warning and steering feel.
- Record every death/retry, where progress restarts, and whether a replayed section feels deserved or tedious.

## Save transfers and platform
- Export a backup from **BONUS LEVELS → BACK UP / RESTORE BONUS SAVES**. Open another compatible copy/browser, preview the JSON, restore explicitly, and test Resume. Keep the old save and backup until confirmed.
- In a slower laptop, compare High and Low render quality for a real five-minute fight at the same resolution. Observe sound stutter, heating, responsiveness, and detail loss.
- If using Safari, explicitly note whether the game was opened as a downloaded HTML file or served over HTTP. These have different browser restrictions. Do not assume a working Safari tab validates another delivery method.
- Mobile menu tapping is not touch gameplay; test mobile only if a future touch-control feature is explicitly implemented.
